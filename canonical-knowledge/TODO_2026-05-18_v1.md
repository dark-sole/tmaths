## 1. Daml: tExpm1 + Pade on tLn/tExp (headline)

The Solidity math libraries are done and green. The remaining work is the Daml
side, untouched this session.

- Add `tExpm1` to `TMaths.daml` — computes `exp(x) - 1` directly to fix
  catastrophic cancellation at deep-OTM (small `x`, where `exp(x)` rounds to
  ~1 and the subtraction loses all precision).
- Apply Pade approximations to `tLn` and `tExp`. Pade coefficients are derived
  offline in mpmath and stored as Decimal literals truncated to 10 places.
  Daml's 10-digit Decimal ceiling caps the achievable gain at roughly 1e-4 to
  1e-7 — set accuracy expectations accordingly, do not promise more.
- Files: `TMaths.daml`, and the consumers `DaletCDF.daml`, `DaletOption.daml`.
- The Dalet paper (`dalet_distribution_06_03.pdf`) section 6 precision tables
  would become outdated by the Pade change. Updating the paper is optional and
  flagged, not part of this task unless the operator asks.

## 3. Gas delta vs pre-split TMaths.sol, and README update

There is currently no measured before/after for the Phase 3 Horner refactor
(exp -> 6-term scaled-integer Horner, ln -> 10-term). The gas tier only exists
post-refactor, so no savings figure can be quoted.

To produce a real figure:
- Run the pre-split `TMaths.sol` (still in the repo, frozen history) through the
  same `TMathHarness` + `TMathGas.t.sol` pattern. Same harness, same measurement
  boundary — the external-call overhead is identical on both sides and cancels,
  so the two point-measurement runs are directly comparable.
- The delta is the real Horner-refactor gas saving (or cost). Record it.

Then update the repo `README.md` — it is now stale. It documents the pre-split,
pre-Horner state: it describes `exp` as "5-term Taylor" (now 6-term Horner), has
no mention of `TMathFusaka` / `TMathLegacy`, quotes the old algorithm's error
figures, and does not mention `tan` reverting `Undefined()` at poles. The README
also quotes gas as ranges (intrinsic compute cost) while the gas tier reports
point measurements (including harness/call overhead) — note both, and explain
the difference so they are not mistaken for a regression.
